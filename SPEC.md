# Chapter spec: Web Development Bootcamp — revision guide

Reader: Rizwan Khalid, a working full-stack/integrations developer (Node.js, Express, REST, some React, Linux). He is revising *The Complete Web Development Bootcamp* (Angela Yu / London App Brewery) and wants to finish the last ~30% (the Web3 / Internet Computer / DApp sections).

Purpose: a REVISION guide in his own words — concise explanations, worked snippets, and cheatsheets. It teaches the concepts so he can revise fast and finish the remaining sections. **It is not a copy of the course.**

## Rules
- Write original explanations and original code examples. Do NOT reproduce the instructor's lecture text, slides, or project code verbatim. Summarise concepts and write your own minimal examples. At most one short quoted phrase if ever needed.
- Be technically correct and current. Where a tool/version matters (e.g. dfx / Internet Computer, React 18 hooks, Mongoose, Express 4/5), state the version assumption. Verify anything you're unsure of with a quick web check and note "as of 2026".
- Keep it practical: each concept gets a 2-6 line explanation, a small code block, and a "gotcha" or "why it matters" line where useful.

## Chapter structure (use these ## sections)
1. `## What this covers` — one short paragraph mapping to the course sections in this chapter.
2. `## Key concepts` — the core ideas, each as a `### Concept` heading with a short explanation + code block.
3. `## Cheatsheet` — a compact table of commands/syntax/APIs for quick revision.
4. `## Common mistakes` — a bullet list of traps.
5. `## Quick self-check` — 5-10 short Q&A (question list, then an `### Answers` subsection).

## Formatting (strict Markdown subset for the PDF builder)
- Headings `#` (chapter title, once), `##`, `###`
- Paragraphs, `- ` bullets, `1.` numbered lists (one level deep max)
- `**bold**` and `` `inline code` `` only
- Fenced code blocks with a language tag; keep code lines <= 90 chars
- Pipe tables with a `|---|` separator; keep cells < 60 chars
- ASCII only; no HTML, images, emoji, or links inside prose (put URLs plainly)
